# Как получить Service Blueprint из БФТ — пошагово

От готового БФТ до страницы карты и архива проекта. Пример — эталон DineClub
(`skills/bft-blueprint/examples/`), эпик `dineclub-restart`.

## Что нужно заранее

- **БФТ эпика.** Его пишет [poh-bft-writer](https://github.com/po-helper-org/poh-bft-writer): `/bft-fast`, затем `/bft-deep`.
  Готовый файл лежит в `.bft/documentation/<epic>/<epic>.md`. Подойдёт и `<epic>-fast.md`, но тогда «Что делаем»
  и «Как это работает» выйдут тоньше: на fast ФТ, ИТ и НФТ ещё скелет.
- **python3.** Для скриптов больше ничего не нужно: ни `npm`, ни сеть.
- **Навык в воркспейсе:**

  ```bash
  curl -fsSL https://raw.githubusercontent.com/po-helper-org/poh-blueprint-writer/main/install.sh | bash
  ```

## Шаг 1. История через экраны

```
/bft-blueprint dineclub-restart --story
```

Агент читает БФТ и пишет `<epic>-story.md`: персонажи, этапы, шаги, экраны, вопросы. По пробелам БФТ он задаёт
тебе один раунд вопросов, до четырёх, с вариантами из БФТ. Остальное оставляет в «Вопросах» открытым.

На выходе — `<epic>-story.html`. Каждый персонаж — ряд, который читается слева направо: «Знакомьтесь» → шаги →
«И с тех пор». Красная точка — открытый вопрос.

## Шаг 2. Согласуй историю

Открой `<epic>-story.html` и проверь:

- у каждого персонажа понятно «было → стало»;
- этапы — те, через которые проходит пользователь;
- экраны и каналы — те, что в БФТ.

Что не так — скажи агенту, он поправит `-story.md` и пересоберёт страницу. Когда всё верно, ответь «да»: агент
ставит `status: Согласован`. Без этого карта не строится — колонки карты берутся из этапов истории.

## Шаг 3. Карта инициативы

```
/bft-blueprint dineclub-restart --map
```

Вводной строкой можно подсказать, кто что делает:
`/bft-blueprint dineclub-restart --map "сканер делает DineClub, проверку билета — TeamA"`.

Агент:

1. Создаёт проект Backlog.md `<epic>-blueprint/` рядом с БФТ (`bft-backlog-init.py`). В нём сразу лежат
   «Карта», «История», встроенный CLI `./backlog.py`, сборка `./blueprint.py`, правила и инструкции.
2. Заполняет «Команды» в «Карте» — из «Зависимостей» БФТ и твоей вводной.
3. Раскладывает БФТ в задачи «Что делаем»: один результат одной команды, постановка ASIS, GAP, TOBE,
   HowToDemo, критерии приемки. Задача стоит на этапе истории.
4. Под каждую задачу создаёт карточки «Как это работает» в слоях Employee Actions, Technology, Backstage, Support.
   В карточке: суть, UserStory, JobStory, «Параметры», «Процесс» по шагам и участникам, HowToDemo.
5. Пишет требования к экранам — документ на экран с вкладками Product, Design, Functions.
6. Если работа затрагивает устройство систем (на карте есть карточки слоя Technology) — этап
   «ADR и Системные требования»: документ «ADR» (варианты ≥2 с оценками «надёжность / скорость
   реализации / соответствие требованиям», выбор TO-BE с обоснованием, узкие места, компромиссы,
   диаграмма AS-IS/TO-BE) и «Системные требования» (по каждому контракту из TO-BE три вопроса:
   данные, источники параметров, преобразования; AS-IS, изменения, вопросы). Отдельные команды —
   `/adr` и `/system-requirements` (запускай в папке проекта); вопросы документов дублируются
   в «Вопросы» «Карты».
7. Всё, чего нет в БФТ, помечает `[УТОЧНИТЬ у {кого}]` и вносит в «Вопросы» «Карты».

Схему BPMN агент не рисует. Её собирает сборка из «Процесса» — текст mermaid в той же карточке.
Картинки экранов сборка рисует из таблицы «Экраны» «Истории» в `backlog/assets/screens/`.

## Шаг 4. Проверка и сборка

Агент прогоняет это сам; руками — из папки проекта:

```bash
cd .bft/documentation/dineclub-restart/dineclub-restart-blueprint
./blueprint.py lint     # 0 ошибок, иначе сборка не пойдёт; БФТ ищет рядом с папкой проекта
./blueprint.py build                                   # схемы, картинки, страница и архив
```

`lint` сверяет карту с БФТ. Каждое ФТ, ИТ, НФТ должно попасть на карту, требований вне БФТ быть не должно, технический язык
в названиях не допускается. Коды ошибок — в `.blueprint/rules/backlog_rules.md`.

`build` собирает:

- `dineclub-restart-map.html` — страницу карты;
- `dineclub-restart-blueprint.zip` — архив всей папки со страницей `blueprint.html`.

Текст страницы берётся только из файлов проекта: строка, которой там нет, валит сборку (`BL032`).

## Шаг 5. Читай карту

Открой страницу. Она должна лежать рядом с папкой проекта: картинки и mermaid страница берёт оттуда. На странице:

- **Что видят** — раскадровка истории; клик по кадру — требования к экрану.
- **Что делаем** — задачи команд по этапам; клик — постановка и вкладка «Исполнение» (JIRA, Confluence, заметка).
- **Как это работает** — четыре ряда слоёв, стрелки между карточками; клик — карточка с UserStory, JobStory,
  схемой BPMN, параметрами и HowToDemo.
- **Архитектура** — если в проекте есть «ADR» и «Системные требования»: варианты и выбор TO-BE,
  узкие места, компромиссы, диаграмма AS-IS/TO-BE и контракты с тремя вопросами на каждый.
- **«!»** в шапке — файлы проекта, из которых это собрано.

## Шаг 6. Уточни и поправь

- **«?» справа сверху** — открытые вопросы. Кликни вопрос, впиши ответ — он отметится ✓.
- **Правая кнопка мыши** по любой секции — замечание; выделенный текст попадёт цитатой.
- **«Скопировать промпт»** — отдай промпт агенту. В нём замечания и ответы, файлы к правке и команды проверки.

Агент правит проект через `./backlog.py`, вписывает ответы в «Вопросы» и снимает `[УТОЧНИТЬ]`. Затем прогоняет
`./blueprint.py lint` и `./blueprint.py build`. Пересобранная страница закрывает учтённые замечания и ответы.
Повторяй, пока вопросов не останется.

## Шаг 7. Отдай карту дальше

- **Команде и стейкхолдерам** — архив `<epic>-blueprint.zip`. Распаковал, открыл `blueprint.html`.
- **Любому ИИ-агенту** — та же папка. Инструкции уже внутри (CLAUDE.md, AGENTS.md, GEMINI.md),
  `./backlog.py` и `./blueprint.py` работают на одном python3.
- **В доску Backlog.md** — если стоит npm-пакет `backlog.md`, `backlog browser` откроет те же задачи и
  нарисует схемы карточек.

## Без агента: только скрипты

```bash
S=<skills_path>/bft-blueprint/scripts
D=.bft/documentation/dineclub-restart
python3 $S/bft-story-lint.py   $D/dineclub-restart-story.md          # история написана вручную
python3 $S/bft-story-render.py $D/dineclub-restart-story.md
python3 $S/bft-backlog-init.py $D/dineclub-restart-story.md          # проект Backlog.md из согласованной истории
# … задачи, карточки и документы — через $D/dineclub-restart-blueprint/backlog.py
python3 $S/bft-backlog-lint.py  $D/dineclub-restart-blueprint --source $D/dineclub-restart.md
python3 $S/bft-backlog-build.py $D/dineclub-restart-blueprint --source $D/dineclub-restart.md
```

Формат задач, карточек и процесса — `skills/bft-blueprint/resources/backlog_rules.md`, готовый образец —
`skills/bft-blueprint/examples/dineclub-restart-blueprint/`.
