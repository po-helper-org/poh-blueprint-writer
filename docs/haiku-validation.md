# Проверка автопилота на слабой модели

Цель — карта и контракты одинаково качественные на любой модели. Метод: агент на **Haiku** проходит
`resources/autopilot.md` от БФТ до сборки без помощи, в изолированной папке, без права править навык,
и ведёт журнал трения. Результат оценивается по смыслу, а не только линтерами; каждый системный
дефект чинится в скриптах и правилах, затем прогон повторяется.

БФТ: `direct-faq` и `club-partners` (фикстуры навыка) и `car-service-booking` — новый эпик, которого навык
не видел при разработке (запись на ТО через приложение банка: внешняя сеть автосервисов, 1С, платежи, кешбэк).

## Что осталось на усмотрение модели

- **Одна команда на две системы** («Разработка» делает Direct и сайт): делится по правилу 4.1 руками —
  модель это делает, каркас — нет.
- **Связи «Вход»/«Выход»** каркас подсказывает по соседству требований, а не по потоку данных:
  модель переписывает их по смыслу.
- **Объём пакетов** `groom fill`: 15–26 пакетов, общие правила повторяются в каждом — дорого, но работает.

## Прототип на Haiku

Шаг «Прототип» (`--prototype`) Haiku проходила по картам, которые сама построила в прогоне 5 (direct-faq,
car-service-booking). Мера — сколько шагов каркаса модель переписала по раскладке (вызов, экраны, успех,
отказ, приложение), не считая значений для демо.

| | Прогон 1 | Прогон 2 | Каркас после правок vs ручная раскладка прогона 2 |
|---|---|---|---|
| direct-faq | 5 шагов переписано | 4 (вызовы и экраны не тронуты) | совпало 10 шагов из 12, разница — подпись приложения |
| car-service-booking | 9 из 12 | 8 | совпало 11 из 17, разница — на какой из шагов с тем же экраном повесить чтение |
| кругов `prototype lint` | 2–3 | 1–3 | — |

Что изменили в каркасе по журналам: вызов запускает экран вызывающей стороны (у `frontend-backend` — экран
UI-карточки), стык, где сервер сам шлёт данные экрану, — за кадром; записывающие вызовы распределяются
жадно, у шага одна кнопка — один вызов; глагол шага ↔ вид операции; отказ — у записывающего вызова;
шаг за кадром встаёт перед шагом, где виден результат.

Осталось модели: порядок шагов внутри этапа между персонажами (история группирует шаги по персонажам,
«закрываю заказ-наряд» до «оплачиваю» каркас не видит) и выбор, на каком из шагов с одним экраном
показать чтение данных.
