# Вход (с пробелами): ADR для «Скидка по билету»

Описание задачи от PO (всё, что известно):

> Делаем фичу «Скидка по билету» в приложении DineClub: гость показывает билет
> на мероприятие в ресторане-партнёре и получает скидку. Из БФТ: валидация билета
> должна занимать до 3 секунд, скидка применяется на кассе ресторана, отчётность
> по применениям — раз в сутки. Участвуют системы: приложение DineClub, касса
> ресторана, API билетного оператора (проверка билета по номеру), каталог акций
> (коды и проценты скидок), сервис сканирования (уже в проде, проверяет QR).
>
> Известные ограничения: сервис сканирования сейчас держит 50 RPS (пик концерта —
> до 300 проверок в минуту по оценке PO), API билетного оператора не публикует
> события — только запрос-ответ, каталог акций — наша система, менять можно.

Чего во входе НЕТ (навигация по пробелам для эталона):

- нет данных о надёжности API билетного оператора (SLA, время недоступности);
- неизвестно, есть ли у API лимиты по частоте запросов;
- не решено, где вести учёт «билет уже использован» для лимита «одна скидка
  на билет».

Эталонный ответ навыка — `examples/adr-output.md`: варианты сравнены, TO-BE
обоснован, неизвестное — `[УТОЧНИТЬ]` + вопросы в «Вопросы» «Карты».
