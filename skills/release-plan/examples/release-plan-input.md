# Вход: план релиза для «Скидка по билету»

Описание задачи от PO (всё, что известно):

> Делаем фичу «Скидка по билету» в приложении DineClub: гость показывает билет
> на мероприятие в ресторане-партнёре и получает скидку. Разработку ведёт
> команда разработки DineClub, стенды поднимает и выкладывает DevOps-команда
> платформы, регресс гоняет QA-команда. Затронуты сервис сканирования билетов
> и база каталога акций — в ней будет миграция. Тимлид разработки утверждает
> переход DEV → STAGE.
>
> Версию 1.0 хотим показать на встрече партнёров через две недели.

Чего во входе НЕТ (навигация по пробелам для эталона):

- кто исполняет миграцию БД каталога акций;
- кто выдаёт тестовые данные и доступы QA на STAGE;
- кто согласовывает окно релиза с бизнесом;
- кто утверждает переход STAGE → PROD;
- нужны ли новые конфиги или секреты сервису сканирования.

Эталонный ответ навыка — `examples/release-plan-output.md`: известное заполнено
из входа, неизвестное — `[УТОЧНИТЬ]`, статус `требует ответа` и вопросы владельцу.
Разделы «Релиз» и «Ворота релиза» эталона валидны схемой этапа Delivery
(`apply` и `lint` без ошибок RL) — это проверяет самотест репозитория.
