# Вход: системные требования для «Скидка по билету»

Описание задачи от PO (всё, что известно):

> Делаем фичу «Скидка по билету» в приложении DineClub: гость показывает билет
> на мероприятие в ресторане-партнёре и получает скидку. Контракты задачи:
>
> 1. Эндпоинт валидации билета — сервис сканирования билетов проверяет билет
>    и отдаёт результат валидации сервису скидок. В запросе: номер билета,
>    дата мероприятия, идентификатор партнёра-ресторана.
> 2. Событие «скидка применена» — сервис скидок публикует событие с кодом акции
>    и суммой скидки; каталог акций по нему учитывает применение.
>
> Данные, которые известны: билеты с номерами и датами отдаёт API билетного
> оператора (система «Продажа билетов», поля external_id и event_date); коды
> акций и процент скидки лежат в базе каталога акций (поле promo_code); сумму
> скидки вычисляем как процент от суммы чека.

Чего во входе НЕТ (навигация по пробелам для эталона):

- из какой системы берётся идентификатор партнёра-ресторана (partner_id)
  и есть ли справочник партнёров вообще;
- есть ли у билетного оператора признак «билет уже использован»;
- в каком виде в каталоге акций лежат лимиты скидок (одно применение на билет?);

Эталонный ответ навыка — `examples/system-requirements-output.md`: известное
заполнено, неизвестное — `[УТОЧНИТЬ]`, привязка «источник неизвестен», вопросы
владельцу в «Открытых вопросах».
