# Вход: системные требования для «Скидка по билету»

Описание задачи от PO (всё, что известно):

> Делаем фичу «Скидка по билету» в приложении DineClub: гость показывает билет
> на мероприятие в ресторане-партнёре и получает скидку. Решение TO-BE из ADR
> (уже принято): контракты `ticket-validation` (эндпоинт валидации билета —
> сервис сканирования проверяет билет и отдаёт результат сервису скидок) и
> `discount-applied-event` (событие «скидка применена» — сервис скидок публикует
> событие, каталог акций по нему учитывает применение).
>
> Данные, которые известны: билеты с номерами и датами отдаёт API билетного
> оператора (система «Продажа билетов», поля external_id и event_date); коды
> акций и процент скидки лежат в базе каталога акций (поле promo_code); сумму
> скидки вычисляем как процент от суммы чека; идентификатор ресторана приходит
> из профиля ресторана в приложении.

Чего во входе НЕТ (навигация по пробелам для эталона):

- из какой системы берётся признак «билет уже использован» — есть ли он
  у билетного оператора или вести локальный учёт;
- в каком виде в каталоге акций лежат лимиты скидок (одно применение на билет?);
- кто владелец данных каталога акций для вопросов об изменениях.

Эталонный ответ навыка — `examples/system-requirements-output.md`: известное
заполнено, неизвестное — `[УТОЧНИТЬ]` + вопросы в «Открытых вопросах».
