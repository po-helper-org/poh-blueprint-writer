# Системные требования: Скидка по билету

Два контракта покрыты: валидация билета (C1) и событие «скидка применена» (C2).
Из 8 параметров у 6 источник известен (билеты — API билетного оператора, коды и
процент скидки — каталог акций), у 2 — «источник неизвестен» (идентификатор
партнёра-ресторана, признак использованного билета).

## Контракты

| ID | Контракт | Стороны | Что фиксирует |
| --- | --- | --- | --- |
| C1 | Эндпоинт валидации билета | сервис сканирования → сервис скидок | тело запроса: номер билета, дата мероприятия, идентификатор партнёра; ответ: результат валидации |
| C2 | Событие «скидка применена» | сервис скидок → каталог акций | поля события: код акции, сумма скидки |

## Параметры

| ID | Контракт | Параметр | Источник | Тип | Обязателен |
| --- | --- | --- | --- | --- | --- |
| P1 | C1 | ticket_number (номер билета) | SRC1 | строка | да |
| P2 | C1 | event_date (дата мероприятия) | SRC1 | дата | да |
| P3 | C1 | partner_id (идентификатор партнёра-ресторана) | [УТОЧНИТЬ: справочник партнёров?] | строка | да |
| P4 | C1 | validation_result (результат валидации) | SRC2 | enum | да |
| P5 | C2 | promo_code (код акции) | SRC3 | строка | да |
| P6 | C2 | discount_amount (сумма скидки) | SRC2 | число | да |
| P7 | C2 | ticket_used (билет уже использован) | [УТОЧНИТЬ: билетный оператор, признак?] | булево | нет |
| P8 | C1 | check_amount (сумма чека) | SRC2 | число | да |

## Источники

| ID | Источник | Система | Сервис | Поле/запись | Отдаёт для |
| --- | --- | --- | --- | --- | --- |
| SRC1 | API билетного оператора | Продажа билетов | REST-вызов external-tickets | external_id, event_date | P1, P2 |
| SRC2 | Сервис скидок | Скидки DineClub | внутренняя логика валидации | результат валидации, сумма чека | P4, P6, P8 |
| SRC3 | База каталога акций | Каталог акций | чтение записи акции | promo_code | P5 |

## Преобразования

| ID | Вход | Преобразование | Выход | Ради чего |
| --- | --- | --- | --- | --- |
| T1 | SRC1.external_id | нормализация формата номера билета | P1 ticket_number | контракт C1 |
| T2 | SRC3.promo_code + SRC2.check_amount | вычисление: процент скидки × сумма чека | P6 discount_amount | контракт C2 и бизнес-логика скидки |
| T3 | SRC2.validation_result + P7 | проверка: валиден и не использован | P4 validation_result | бизнес-логика валидации |
| T4 | SRC1.event_date | проверка даты мероприятия не позже текущей | признак валидности билета | бизнес-логика валидации |

## AS-IS источников

| Источник | Есть уже | Отдаётся сырым | Отсутствует |
| --- | --- | --- | --- |
| SRC1 | external_id, event_date по каждому билету | даты в формате ISO без тайм-зоны ресторана | признак «билет уже использован» — [УТОЧНИТЬ: что есть в билетном операторе] |
| SRC2 | сумма чека из кассы, результат валидации внутри сервиса | — | — |
| SRC3 | promo_code и процент скидки по каждой акции | процент хранится строкой «15%», не числом | лимит «одно применение на билет» — [УТОЧНИТЬ: что есть в каталоге] |

## Изменения

| ID | Источник | Изменение | Ради чего |
| --- | --- | --- | --- |
