# Контракты стыков — Design First

Карта говорит, **что** происходит на шаге пути. Контракт говорит, **как стыкуются системы**, чтобы
шаг прошёл: кто кого вызывает, какие поля уходят и приходят, откуда каждое поле в БФТ, что
возвращается при отказе, через какую цепочку данные превращаются в ответ, какие данные нужны из
хранилища. Контракты читают фронт, бэк и внешняя сторона, по ним же соберётся прототип.

Один контракт — один файл `contracts/C-N.md` в папке проекта, по шаблону `.blueprint/templates/contract.md`.
Проверка — `./blueprint.py contracts`: коды CT, 0 ошибок до показа.

## Контракт — проектное решение

БФТ говорит, **что** должно произойти и какие данные для этого нужны. Метод, путь, имена полей,
коды ошибок и пример ответа в БФТ не пишут — их **проектирует контракт**, и это не выдумка, а работа
Design First. Выдумкой было бы новое требование: поле, которое не нужно ни одному требованию, порог
или правило без источника. Поэтому:

- метод, путь, имя поля, код ошибки — называешь сам, по смыслу требования и «Процесса» карточек;
- у каждого поля «Источник» — требование, которому это поле нужно (ФТ, ИТ, ПТ, параметр P5, инвариант I2), а не место, где поле «написано»;
- значение, которого нет в БФТ (лимит, срок, канал), — `[УТОЧНИТЬ у …]` в «Источнике» и строка «Вопросов» карты; в примере ответа — правдоподобное значение того же типа.

## Когда нужен контракт

Решение по таблице, без обдумывания:

| На карте | Контракт |
|---|---|
| связь `(BP-x.y)` экрана Technology с карточкой Backstage — даже у одной команды | **да**, обычно `frontend-backend` — обе карточки в `cards:` (иначе `CT020`) |
| связь `(BP-x.y)` между карточками разных команд, одна из них в Backstage | **да**, `service-service` |
| внешняя система вызывает нас или мы её (партнёр, сканер, провайдер билетов) | **да**, `boundary: external` |
| экран Technology получает или отправляет данные | **да**, `boundary: frontend-backend` |
| карточка Backstage читает или пишет своё хранилище | **да**, `boundary: service-db` |
| связь через Support: макет, правило, канал, договорённость | нет — это не данные |
| связь внутри одной команды | нет, если сторона не внешняя |

## Шапка

| Поле | Что писать |
|---|---|
| `id` | `C-1`, `C-2` … — совпадает с именем файла; номера не перенумеровываются |
| `title` | что происходит на стыке фразой для человека: «Официант сканирует билет» |
| `boundary` | `external` · `frontend-backend` · `service-service` · `service-db` — по таблице выше |
| `caller`, `callee` | кто вызывает и кто отвечает: команда из «Команд» карты или система из «Процесса» карточки |
| `op` | `МЕТОД /путь`: GET — прочитать, POST — создать или выполнить действие, PATCH — изменить часть, DELETE — убрать. Путь — `/v1/<сущность во мн. числе>[/{id}][/<действие>]`. У `service-db` строки нет |
| `cards` | ID карточек «Как это работает», которые обслуживает стык |

## Разделы

| Раздел | Обязателен | Как заполнять |
|---|---|---|
| `## Запрос` | кроме `service-db` | поле латиницей `snake_case`; тип `string · integer · number · boolean · array · object`; `Обяз.` — да/нет; `Где` — `path · query · body · header`; параметр пути `{id}` — строкой с `path` (`CT010`) |
| `## Ответ` | кроме `service-db` | хотя бы одно поле; вложенное — через точку: `promo.discount`, элемент списка — `items.name` |
| `## Пример ответа` | кроме `service-db` | блок ```` ```json ```` с каждым полем «Ответа» — из него MockAPI прототипа отдаёт ответ. Значения — как их вернёт система, с типом из «Ответа»: `10`, `"valid"`, `true`, `"2026-03-01"`; пояснение и ID требования вместо значения — `CT012` |
| `## Ошибки` | у `external` | статус 4xx/5xx, код `ЗАГЛАВНЫМИ_С_ПОДЧЁРКИВАНИЕМ`, когда — по-русски со ссылкой на требование. У внутренних стыков без ошибок — `CT022` |
| `## Sequence` | кроме `service-db` | `- Кто -> Кому: вызов(поля)` и `- Кто --> Кому: поля ответа`. Первая строка — `caller -> callee`, на каждый вызов — ответ |
| `## Цепочка` | когда в Sequence больше двух участников (`CT021`) | шаг · кто · вход · что делает · выход. Вход — поля «Запроса» или выходы прошлых шагов, ответ собирается из выходов (`CT008`). Группа полей — `ticket{status, event_date}` |
| `## Данные` | у `service-db` | хранилище и **какие данные нужны** обычными словами — без таблиц, ключей, индексов и SQL (`CT009`): устройство хранилища — работа СА |

## Источник каждого поля

У каждого поля запроса, ответа и строки данных — `Источник`: ID требования из БФТ (`ФТ-4`, `ИТ-3`,
`ПТ-1`) или `[УТОЧНИТЬ у {кого}]` (`CT005`). Поле без требования — выдумка: либо убери, либо
вопрос в «Вопросы» карты. ID копируй из `./blueprint.py reqs`; с БФТ рядом линтер сверяет их (`CT006`).

## Фронт и бэк видят разное

- **Фронту** хватает шапки, «Запроса», «Ответа», «Ошибок» и примера: что отправить и что показать.
- **Бэку** — ещё «Sequence» и «Цепочка»: к кому он обращается дальше и как вход превращается в ответ.
- **Хранилищу** — отдельный контракт `service-db`: какие данные нужны и по какому требованию.

Сложная обработка за кадром не расписывается во фронтовом контракте: фронт видит вход и выход,
а цепочку — тот же контракт в разделе «Цепочка».

## Проверка

| Код | Что ловит |
|---|---|
| CT001 | файл не контракт: frontmatter, `id` = имя файла, повтор ID |
| CT002 | шапка: поля, `boundary` из списка, `op` «МЕТОД /путь» |
| CT003 | `cards:` ссылается на карточку, которой нет |
| CT004 | разделы и колонки шаблона, имена полей, пример ответа с полями ответа, ошибки внешнего стыка |
| CT005 | у поля нет источника |
| CT006 | ID требования нет в БФТ |
| CT007 | Sequence: начало с `caller -> callee`, ответ на каждый вызов, участники известны карте |
| CT008 | цепочка: вход без источника, поле ответа не собрано |
| CT009 | устройство хранилища в «Данных» или «Цепочке» |
| CT010 | параметр пути не описан в «Запросе» |
| CT011 | в контракте остались места `{{…}}` каркаса |
| CT012 | пример ответа: значение не того типа или пояснение вместо значения |
| CT020 | предупреждение: стык на карте без контракта |
| CT021 | предупреждение: за вызываемой системой есть участники, а «Цепочки» нет |
| CT022 | предупреждение: внутренний стык без единой ошибки |
