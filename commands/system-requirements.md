## Использование

```
/system-requirements [текст | путь к файлу] [--bft <путь к БФТ>] [--project <epic>-blueprint]
```

**Параметры:**
- `[текст | путь к файлу]` — описание задачи: контракты (эндпоинты, события, форматы), системы, где какие данные лежат. Файл — тот же текст целиком.
- `--bft <путь>` — опц., БФТ эпика: функциональные и интеграционные требования — откуда брать контракты и системы.
- `--project <epic>-blueprint` — опц., проект Service Blueprint: навык допишет разделы «## Контракты» … «## Открытые вопросы» в `plan/map.md` и применит их (`./blueprint.py apply`).

## Примеры

```
/system-requirements Делаем скидку по билету: эндпоинт валидации билета в сервисе сканирования, событие «скидка применена» в каталог акций; билеты отдаёт API билетного оператора
/system-requirements brief.md --bft .bft/documentation/skidka-bileta/skidka-bileta.md
/system-requirements brief.md --project skidka-bileta-blueprint
```

## Что делает

1. Читает вход: контракты (из текста и ИТ-требований БФТ), системы и где какие данные лежат.
2. Для каждого контракта отвечает на три обязательных вопроса: (1) какие данные нужны контракту — параметры с типом и обязательностью; (2) откуда берётся каждый параметр — источник `система / сервис / поле / справочник`; (3) какие преобразования нужны для контрактов и бизнес-логики — обогащение, валидация, конвертация, вычисление, джойн.
3. **Не выдумывает.** Источник параметра не сказан во входе — поле `[УТОЧНИТЬ: …]`, привязка «источник неизвестен», вопрос в «Открытые вопросы». Про состояние источников спрашивает, если вход молчит.
4. Данных критически не хватает (нет ни контракта, ни системы) — возвращает только вопросы, документы не строит.
5. С `--project` кладёт разделы в `plan/map.md` и прогоняет `./blueprint.py apply` и `./blueprint.py lint` (гейты AR: форма таблиц, ссылки на контракты/источники). Вопросы, ложащиеся на задачи карты, дублирует в «## Вопросы» плана с BP-ID в «Где».

Формат ответа и правила — `../skills/system-requirements/SKILL.md`; эталоны — `../skills/system-requirements/examples/` (вход с пробелами и вход без данных).

## Важно

**Честность важнее полноты.** Лучше вопрос без источника, чем источник, придуманный за владельца системы. Каждый «источник неизвестен» имеет `[УТОЧНИТЬ]` и вопрос; каждое `[УТОЧНИТЬ]` — вопрос.

**Навык не проектирует новые контракты и архитектуру** — это этап ADR. Не выдаёт доступы и не трогает системы — это Delivery. Вопросы людям не рассылает: список «кому — что» отдаётся владельцу.
